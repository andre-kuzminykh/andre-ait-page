# Анимированная графика поверх видео — где ИИ создаёт ценность (слайды 13–16)

Элементы слайдов 13–16 лекции 1 (`/automation/1/`) — «Модель создания ценности»,
«Процессная архитектура», «ИИ как нервная система», «Где ИИ создаёт ценность» —
разложенные по озвучке вертикального ролика 1080×1920: элемент появляется ровно
тогда, когда о нём говорят. Четвёртый ролик серии.

Открыть: <https://andre.technology/automation/1/overlay-value/>

## Постоянные правила подачи

Те же семь, что у прошлых роликов.

1. **Никаких прямоугольных блоков.** Круг — единственная допустимая оправа.
2. **Никаких заголовков.** Заголовки слайдов в кадр не идут.
3. **Только крупный текст**, минимум 24px при ширине кадра 1080.
4. **Однотипные элементы — в ряд** (или сеткой, если в ряд не влезают).
5. **Слова не переносятся.**
6. **Графика не доходит до картин на стене** (верх рамок — y638): зона 238…630 — поднята под самую шапку, чтобы блоки стояли выше.
7. **Текст белый.**

Выделение: пока об элементе говорят, он подрастает (×1.12) и берётся во
внешнее кольцо, потом плавно возвращается. Соседи **не гаснут**. Цвета
чередуются фиолетовый / оранжевый. Шапка AIT + «АКАДЕМИЯ ДАТАИСТА» — весь
ролик, кроме обложки.

Времена стоят прямо в разметке: `data-in` — когда элемент выходит,
`data-out` — когда уходит, `data-cur` — окна «о нём говорят прямо сейчас».
Сдвинулась озвучка — правятся только эти числа.

**Каждый элемент и каждое кольцо сверены с дорожкой:** их секунда обязана
попадать внутрь реплики, иначе графика идёт сама по себе, а речь сама по
себе. Проверка печатает для каждого элемента, что именно звучит в его
момент.

## Собрать ролик, потом нарезать на четыре

```
sh собрать.sh "ваше видео.MOV"                       # один ролик целиком
sh нарезать.sh "ваше видео-готовый.mp4" 44 82 129    # четыре части
```

Числа реза — по границам слайдов: 44 (конец RUN/CHANGE/DISRUPT), 82 (конец
процессной архитектуры), 129 (конец нервной системы).

**Второй раз собирать `…-готовый.mp4` нельзя**: субтитры в нём уже вжжены, и
новый заход положил бы поверх них вторую строку. Скрипт видит такое имя и
останавливается.

**Обложки уже готовы:** `cover.png` — на весь ролик, `cover1.jpg`…`cover4.jpg` —
по одной на часть (в jpg), с подписью «Часть N» под тайтлом. Скрипт нарезки видит
пронумерованные обложки и не рисует подпись поверх второй раз.

## Субтитры

**Ни одна реплика не переносится на две строки.** Владелец: «у меня на видео
субтитры друг на друга накладывались». Наслаивались не соседние реплики — их
границы и так совпадают — а строки ВНУТРИ одной: четыре слова кеглем 50px не
влезали в полосу 940px («различных пользовательских сценариев.» — 1173px) и
уезжали на вторую строку. Каждая реплика измерена настоящим шрифтом и, если не
влезала, разрезана по словам: время делится пропорционально длине кусков, рез
не ставится на предлоге и не начинает строку с тире. Слова и границы речи не
тронуты — их было 366 и осталось 366, самая широкая строка теперь 894px.

133 реплики, 366 слов. **Времена из распознавания, слова из сценария**:
распознавалка писала «произменения» вместо «про изменения», рвала
«Run -Change-Disrupt» и ставила водяной знак TurboScribe. После реза по ширине
в реплике бывает от одного до четырёх слов — правило теперь не «сколько слов»,
а «влезает в одну строку», и его сторожит тест: ширина считается по метрикам
самого ttf (`tools/ttf_width.py`), без браузера.

**Кегль вжжённых субтитров = кегль на странице.** libass (как и VSFilter)
понимает `Fontsize` не как размер em, а как высоту строки `winAscent+winDescent`
из таблицы OS/2. У Montserrat Black это 1.562em, поэтому прежний «Fontsize 53»
рисовался в кадре как 34px — в полтора раза мельче, чем показывает превью и
чем лежит в запасном слое. Скрипт умножает кегль на 1.562, и обе дороги сборки
дают один и тот же кадр (проверено: строка встаёт пиксель в пиксель на место
строки из слоя).

Слова живут в `субтитры.srt` и только там: страница-превью читает тот же файл,
который вжигает `собрать.sh`. Перерендеривать графику ради правки слова не
нужно — субтитров в слое графики нет. Но если ваш ffmpeg без libass, текст
берётся из готового слоя `subs_c.mp4`/`subs_a.mp4`: правку слов в этом случае
скрипт заметит по хэшу `субтитры.sha` и честно остановится, а не соберёт ролик
со старым текстом.

## Слой графики

`overlay_c.mp4` — цвет, `overlay_a.mp4` — маска прозрачности (в mp4 нет альфы,
`alphamerge` сшивает их обратно). Слой 169.0 c при дорожке 167.1: в хвосте
остаётся одна шапка, и `собрать.sh` держит этот кадр до конца дубля
(`tpad=stop=-1:stop_mode=clone`) — шапка не пропадает, даже если ваш дубль
длиннее.

Пересобрать страницу из исходников: `python3 tools/build_value.py`.
Перерендерить слой: `python3 tools/render_overlay.py 169.0 <порт> <папка> "&subs=0"`.

## Параметры в адресе

| Параметр | Что делает |
|---|---|
| `?t=95` | открыть сразу на 95-й секунде |
| `?src=clip.mp4` | подхватить видео, лежащее рядом с файлом |
| `?guides=1` | показать границы зоны и верх картин |
| `?scrim=0` | убрать затемнение верха кадра |
| `?subs=0` | выключить субтитры |
| `?only=subs` | оставить в кадре только субтитры (рендер запасного слоя) |
| `?cover=0` | убрать заставку |
| `?rec=1` | режим записи без панели |
| `?bg=none` | прозрачный фон — под захват |
