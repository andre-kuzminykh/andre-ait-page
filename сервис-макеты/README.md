# Макеты интерфейса сервиса «Ролики»

Шесть экранов к предложению [`СЕРВИС-UX.md`](../СЕРВИС-UX.md) — не картинки из
головы, а живая страница: `index.html` открывается в браузере, все шесть
экранов лежат на ней подряд, править можно прямо там.

Открыть: <https://andre.technology/сервис-макеты/>

| Экран | Что показывает |
|---|---|
| `1-ролики.png` | список роликов: статусы, на каких правилах собран, «Новый ролик» |
| `2-материалы.png` | вход — дубль, дорожка, обложка, сценарий — и проверки входа с готовым решением («Сдвинуть на 41.9») |
| `3-раскадровка.png` | главный экран: лента сцен, играющее превью, инспектор, замечание с кнопкой починки, правка словами |
| `4-сборка.png` | очередь: шесть этапов с честным прогрессом и журналом |
| `5-готово.png` | части с обложками, отчёт проверок, слепок сборки |
| `6-правила.png` | правила как данные: значение, откуда взялось, проверяется ли |

Данные на макетах — настоящие: кадры и обложки девятой лекции
(`automation/1/overlay-roles/`), её тайминги, её замечание про «Мыслить как
архитектор» и её рез 41.9.

## Пересобрать скриншоты

```
python3 сервис-макеты/снять.py            # замер + шесть PNG
python3 сервис-макеты/снять.py --только-замер
```

Скрипт сначала меряет, не вылезает ли что-то за рамку экрана 1440×900, и
только потом снимает. Это не формальность: первый заход отдал макет, у
которого нижние панели третьего экрана были срезаны рамкой, — `.main` без
`min-height:0` растёт по min-content, и ряд грида становится выше 900px.
Скриншоты снимаются в двойном разрешении (2880×1800).
