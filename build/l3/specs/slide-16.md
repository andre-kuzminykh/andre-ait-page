## Направление: как сделать инфографику лучше прежней

Аналогия с официантом как схема: Гость (клиент) → Официант (API, меню = документация) → Кухня (сервер)
→ блюдо (ответ); стрелки бегут туда и обратно. Ниже анатомия запроса: адрес · параметры · заголовки ·
тело; четыре метода цветными плашками GET получить · POST создать · PATCH изменить · DELETE удалить; доступ —
ключи, токены, OAuth; ответ 2xx — успех, иначе ошибка (два светофора). Отдельно вебхук: система сама
сообщает о событии вместо постоянных проверок (сравнение «опрос каждые 5 минут» против «звонок, когда
случилось»).

## 16. API и внешние системы  (Блок 4. ИИ-операции и инструменты)

Хотите строить ИИ-агентов — придётся понимать базовую механику API.
Часто инструменты агента взаимодействуют с внешними системами через API.
Проще всего представить API как официанта между гостем и кухней. Вы выбираете действие из меню, передаёте заказ, кухня выполняет его и возвращает результат.
Технически всё похоже: клиент отправляет запрос серверу и получает ответ. Документация говорит, какие действия доступны, какие параметры передать и что вернётся.
В запросе есть адрес, параметры, заголовки и иногда тело. GET — получить, POST — создать, PATCH — изменить, DELETE — удалить.
Доступ дают ключи, токены или OAuth. Если ответ начинается на 2 — успех, иначе - ошибка.
А вебхуки позволяют системе самой сообщать о событиях вместо постоянных проверок.
По сути, API — язык, через который решение агента превращается в реальное действие.
