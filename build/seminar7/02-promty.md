# Семинар 7 · Промты для своего портала

Промты идут по порядку, каждый следующий берёт результат предыдущего.
Места, куда вставлять своё, выделены так: **⟦ВСТАВЬТЕ: …⟧**.

---

## Промт 1 · TO-BE и граф навыков → инструкция

> **Что вставить:** ⟦ВСТАВЬТЕ: код или описание TO-BE⟧ и ⟦ВСТАВЬТЕ: граф навыков агентов⟧ — из практик лекций 2 и 3.

```
Ты — методолог внедрения ИИ-агентов. По модели TO-BE и графу навыков агентов напиши инструкцию для сотрудников корпоративного портала.

Для каждого процесса:
1. Название процесса и его цель одной строкой.
2. Роли: название роли и тип работы — один из четырёх:
   view — только смотрит дашборд;
   decide — получает уведомления агента и принимает решения;
   recommend — агент приносит ему информацию, он оценивает её пользу;
   chat — общается с агентом в чате и оценивает ответы.
   У одной роли может быть несколько процессов.
3. Агенты процесса: для каждого — 4–6 подробных шагов «как работать с агентом», от второго лица: кто что делает, где решение за человеком.
4. Внутри шагов: когда агент передаёт задачу человеку и что человеку отмечать для дообучения.
Названия систем и инструментов не упоминай.

Пиши просто, без канцелярита. Каждое правило можно проверить.

TO-BE:
"""
⟦ВСТАВЬТЕ: код или описание TO-BE⟧
"""

Граф навыков агентов:
"""
⟦ВСТАВЬТЕ: граф навыков агентов (mermaid или список)⟧
"""
```

## Промт 2 · Инструкция → карточки агентов с обучением

> **Что вставить:** ⟦ВСТАВЬТЕ: результат промта 1⟧.

```
По инструкции составь для каждого агента карточку для реестра и обучающий урок для сотрудников.
Сотрудник должен после урока понимать, зачем агент, что он делает сам, где решение за человеком и как не ошибиться.

Для каждого агента:
1. Название — 2–4 слова.
2. Что делает — одно предложение.
3. Роли (может быть несколько) и процессы (может быть несколько).
4. Коротко: как работать — 5–6 шагов одним списком, от второго лица, включая когда агент передаёт задачу человеку и что отмечать.
5. Урок:
   - Зачем этот агент — 2–3 предложения: как было раньше, что болело, что изменилось;
   - Что делает агент — 3–5 пунктов;
   - Что делаете вы — 2–4 пункта, с названием роли в начале («Партнёр: …»);
   - Разбор на примере — реалистичная ситуация из нашего бизнеса с цифрами: ситуация → что делает агент → что делает человек и что попадает в журнал;
   - Частые ошибки — 3 пункта, чего сотрудник не должен делать и почему.

Пиши просто, без канцелярита. Названия систем и инструментов не упоминай.

Инструкция:
"""
⟦ВСТАВЬТЕ: результат промта 1⟧
"""
```

## Промт 3 · Метрики дашборда

> **Что вставить:** ⟦ВСТАВЬТЕ: результат промтов 1 и 2⟧.
> И обязательно ⟦ВСТАВЬТЕ: свои метрики⟧: бизнес-метрики процессов с целями из практики лекции 2 и метрики качества агентов из лекции 6 — с текущими и целевыми значениями, если есть.

```

- минимум 2 в процентах (вид donut) и 1–2 числом (вид kpi);

- обязательно метрика качества агента для роли: доля одобренных решений (decide), доля полезных рекомендаций (recommend), доля хороших ответов (chat) или доля принятых ответов (view).
Плюс для каждой роли 7 чисел за неделю (пн–вс) и подпись графика («решений в день»).

Мои метрики (процессы — из практики лекции 2, агенты — из лекции 6):

## Промт 4 · Всё вместе → блок CONFIG для портала

> **Что вставить:** ⟦ВСТАВЬТЕ: результаты промтов 1–3⟧ и ⟦ВСТАВЬТЕ: блок CONFIG из образца corporate_ai_portal.html⟧.
> Результат этого промта целиком заменяет блок `CONFIG` в вашей копии `corporate_ai_portal.html`.

```
Собери JavaScript-объект CONFIG для портала строго по структуре образца ниже. Поменяй только содержимое, названия полей оставь как есть.

Правила:
- processes: [{id:'p1', name}] — id латиницей p1, p2…
- roles: [{id:'r1', name, type}] — type строго одно из: view, decide, recommend, chat.
- agents: [{id:'a1', name, roles:['r1'], processes:['p1'], does, steps:[…], learn:{why, agent:[…], you:[…], example:{case, agent, you}, mistakes:[…]}}] — roles и processes ссылаются на id выше.
- metrics: {r1:[{name, v, t, kind}]} — по 4 на каждую роль; для kind 'donut' v — процент 0–100.
- week: {labels:['пн','вт','ср','чт','пт','сб','вс'], r1:[7 чисел], …}; weekLabel: {r1:'…', …}.
- queue: 3 уведомления для роли decide: {id:'D-…', agent:'a…', text} — ситуации, где агенту нужно решение человека.
- reasons: 5 причин решения — это разметка для дообучения.
- recs: 3 рекомендации для роли recommend — конкретные, с цифрами и сроками.
- answers: 3 ответа агента для чата, включая один честный отказ «передаю эксперту».
- materials: оставь все материалы с role:'all' из образца и при желании добавь 2–4 материала под свои роли (role:'r2' и т. д.) с реальными ссылками.
Верни только объект: const CONFIG = { … }; — без пояснений.

Данные:
"""
⟦ВСТАВЬТЕ: результаты промтов 1–3⟧
"""

Образец:
"""
⟦ВСТАВЬТЕ: блок CONFIG из образца corporate_ai_portal.html⟧
"""
```

## Промт 5 · База знаний для живого чата (по желанию)

> **Что вставить:** ⟦ВСТАВЬТЕ: карточку агента для роли chat из промта 2⟧ и ⟦ВСТАВЬТЕ: свои материалы — методология, регламенты, прошлые кейсы⟧.
> Результат вставляется в узел **Промт агента** воркфлоу `n8n-chat-openai.json` вместо `⟦ВСТАВЬТЕ: база знаний…⟧`.

```
Ты готовишь базу знаний для ИИ-агента, который отвечает сотрудникам в чате корпоративного портала.
Собери из материалов ниже компактную базу — не больше 1500 слов:
- разделы с короткими заголовками (методология, этапы и сроки, роли, частые вопросы);
- в каждом разделе — факты списком: цифры, сроки, правила;
- прошлые кейсы — по одной строке: номер (К-001…), отрасль, задача, результат;
- ничего не придумывай: если данных нет, раздел не пиши.
В конце — 5 вопросов, на которые агент должен честно ответить «передаю эксперту», потому что их нет в базе.

Агент:
"""
⟦ВСТАВЬТЕ: карточку агента для роли chat из промта 2⟧
"""

Материалы:
"""
⟦ВСТАВЬТЕ: свои материалы — методология, регламенты, прошлые кейсы⟧

Проверка после подключения: задайте агенту два вопроса из базы и один из пяти «чужих».
По первым он должен назвать источник, по последнему — написать «передаю эксперту».

## Промт 6 · Дизайн портала в стиле своей компании (бонус)

> **Для тех, кто закончил раньше.** Меняется только внешний вид — логика, журнал, чат и блок CONFIG остаются как есть.
> **Что вставить:** ⟦ВСТАВЬТЕ: брендбук — цвета, шрифт, ссылка на логотип⟧ и ⟦ВСТАВЬТЕ: весь файл corporate_ai_portal.html целиком⟧.
> Лучше всего работает в Claude (Artifacts) или ChatGPT (Canvas): результат сразу видно.

```
Ты — дизайнер интерфейсов. Ниже рабочий HTML-файл корпоративного портала. Перерисуй его в стиле нашей компании.

Можно менять:
- CSS: цвета, шрифты, скругления, тени, отступы, фон;
- шапку: добавить логотип слева от названия;
- иконки (набор Phosphor уже подключён) и оформление карточек, кнопок, дашборда.

Нельзя менять:
- блок между строками «КОНФИГ: ментор меняет только этот блок» и «дальше ментору ничего менять не нужно» — ни одного символа;
- JavaScript-функции, их названия, id и классы, на которые ссылается скрипт (#app, #chat, #q, #modal, #toast, .fold, .notif и другие);
- порядок блоков: агенты → дашборд → работа роли → вебинары;
- тексты кнопок и подсказок (i).

Требования:
- читается на телефоне шириной 390 px, без горизонтальной прокрутки;
- контраст текста не ниже 4.5:1;
- кольца и столбцы дашборда — в цветах бренда.

Верни файл целиком, от <!DOCTYPE html> до </html>, без пояснений.

Брендбук:
"""
⟦ВСТАВЬТЕ: брендбук — основной и дополнительный цвета (HEX), шрифт, ссылка на логотип⟧
"""

Файл:
"""
⟦ВСТАВЬТЕ: весь файл corporate_ai_portal.html целиком⟧
"""
```

Проверка после промта 6: пройдите чек-лист из инструкции ещё раз. Если что-то перестало работать — верните
прежний файл и повторите промт, добавив: «В прошлый раз сломалось ⟦ВСТАВЬТЕ: что именно⟧ — не трогай это».
