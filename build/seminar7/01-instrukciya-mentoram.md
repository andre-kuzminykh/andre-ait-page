# Семинар 7 · Инструкция для ментора: свой портал ИИ-агентов за семинар

**Что получится:** один HTML-файл — корпоративный портал вашей компании.
В нём реестр агентов по ролям, дашборд для каждой роли, уведомления с решениями,
рекомендации, чат с агентом, инструкции к агентам, журнал для дообучения и вебинары.
Образец — `corporate_ai_portal.html` («Корпоративный ИИ-портал», консалтинг). Структура у всех одинаковая, меняется только содержимое.

**Что понадобится:**
- ваша модель TO-BE (практика лекции 2);
- граф навыков агентов (практика лекции 3);
- **метрики для дашборда**:
  - бизнес-метрика каждого процесса и её цель — из практики лекции 2 (шаг 1: цель, метрика, границы; сравнение AS-IS и TO-BE);
  - метрики качества агентов — из лекции 6 (тестирование и мониторинг): доля верных ответов, передач человеку, ошибок, время ответа;
  - текущие значения и целевые, хотя бы примерные. Если данных нет — промт 3 предложит правдоподобные, их помечают как «пример»;
- файл `02-promty.md` с промтами;
- файл `03-podklyuchenie.md` — если хотите живые данные и живой чат;
- файл `n8n-chat-openai.json` — готовый воркфлоу n8n для чата с OpenAI (импортируется одной кнопкой).

## Что сказать участникам (3 минуты)

> Сегодня каждый собирает портал своей компании: место, где сотрудники работают с ИИ-агентами.
> Берём ваш TO-BE и граф навыков агентов. Четыре промта превращают их в конфиг портала,
> вы вставляете его в образец — и портал готов. Сверху агенты вашей роли и инструкция к каждому,
> ниже дашборд с целями, ниже работа роли: партнёр принимает решения, менеджер оценивает
> рекомендации, методолог спрашивает агента в чате. Каждое действие попадает в журнал — это
> датасет для дообучения агентов. Кто успеет — подключит чат к OpenAI через n8n и журнал к Google Таблице.

Порядок показа образца: выбрать «Партнёр» → одобрить уведомление → открыть «Журнал» (строка появилась)
→ «Методолог» → спросить в чате, поставить 👎 и написать правильный ответ → «Инструкция» у агента
→ в журнале «Сбросить демо» перед следующим показом.

## Как устроен портал

| Что видит человек | Откуда берётся |
|---|---|
| **Агенты** (все блоки сворачиваются, рядом с заголовком — счётчик) | Сверху: название портала, выбор роли, кнопка «Журнал». Карточки агентов роли с кнопкой «Инструкция» |
| **Дашборд** | Метрики роли (кольца и числа), график за неделю, блок работы роли, «Раскрыть подробнее» |
| **Инструкция и обучение** | Коротко: как работать (шаги). Ниже урок: зачем агент, кто что делает, разбор примера, частые ошибки. Роль и агента можно выбрать |
| **Вебинары** | В самом низу, под всем. «Добавить материал»: ссылка, название, описание, роль |
| **Журнал** | Все решения, оценки и исправления. Это датасет для дообучения. Менять решения может только роль с типом `decide`. Кнопки «CSV» и «Сбросить демо» |

Блок работы роли на дашборде задаётся полем `type`:

| `type` | Что видит роль |
|---|---|
| `view` | только дашборд |
| `decide` | уведомления агента: человек выбирает решение и причину, уведомление исчезает |
| `recommend` | агент сам приносит информацию, человек ставит 👍 или 👎 |
| `chat` | чат с агентом; к плохому ответу пишется правильный. Без `CHAT_WEBHOOK` агент отвечает примерами из `answers`, с ним — живой моделью |

Всё содержимое портала — в одном блоке `CONFIG` в начале скрипта, между строками
`КОНФИГ: ментор меняет только этот блок` и `дальше ментору ничего менять не нужно`.
Ниже этого блока ничего не трогайте.

## Порядок работы на семинаре (≈ 60 минут)

### Шаг 1. Процессы и роли (10 мин)
Выпишите процессы из своего TO-BE. Для каждого определите, какие роли
в нём участвуют и как: только смотрят, принимают решения, получают рекомендации
или общаются с агентом. У одной роли может быть несколько процессов и агентов.

### Шаг 2. Инструкция и карточки агентов (15 мин)
1. Откройте `02-promty.md`, **промт 1**. Вставьте свой TO-BE и граф навыков.
   Получите подробное описание каждого агента: когда запускается, что получает, что делает, что выдаёт, где решение за человеком, когда передаёт задачу, что нельзя, что отмечать для дообучения.
2. **Промт 2** — карточки агентов: что делает, роли, процессы, короткие шаги и урок с примером и ошибками.

### Шаг 3. Метрики дашборда (10 мин)
**Промт 3.** Вставьте в него свои метрики процессов и агентов (см. «Что понадобится»).
Модель разложит их по ролям: у каждой роли — все её метрики. У каждой метрики значение, цель и вид:
- `donut` — кольцо, для процентов;
- `kpi` — число.

Плюс данные за неделю для графика.

### Шаг 4. Сборка конфига (10 мин)
**Промт 4** соберёт всё в готовый блок `CONFIG`. Туда входят примеры уведомлений,
рекомендаций, ответов чата и материалы под ваши роли.

### Шаг 5. Вставить и проверить (10 мин)
1. Скопируйте `corporate_ai_portal.html` и назовите копию, например `portal-моя-компания.html`.
2. Замените блок `CONFIG` целиком на результат промта 4.
3. При желании поменяйте название портала в `PORTAL_NAME` в начале скрипта.
4. Откройте файл в браузере и пройдите чек-лист ниже.

### Шаг 6. Живой чат с OpenAI (по желанию, 10 мин)
1. В n8n: **Workflows → Import from File** → `n8n-chat-openai.json`.
2. В узле **OpenAI** выберите учётные данные OpenAI (Credentials → OpenAI API → ваш ключ).
3. В узле **Промт агента** замените `⟦ВСТАВЬТЕ: база знаний…⟧` на свою базу знаний
   (результат **промта 5** из `02-promty.md`).
4. Включите воркфлоу (**Active**), скопируйте **Production URL** вебхука и вставьте его в `CHAT_WEBHOOK`.
5. Откройте портал, выберите роль с чатом и задайте вопрос.

Ключ OpenAI хранится только в n8n. **Никогда не вписывайте ключ в HTML** — его увидит каждый, кто откроет файл.
Подробно — в разделе 4 файла `03-podklyuchenie.md`.

### Шаг 7. Журнал в Google Таблицу и дашборд (по желанию, 10+ мин)
Впишите `N8N_WEBHOOK` и `DASHBOARD_URL`, как описано в `03-podklyuchenie.md`.

## Чек-лист перед сдачей
- [ ] В реестре переключаются все роли, у каждой роли есть хотя бы один агент.
- [ ] У каждого агента открывается «Инструкция и обучение»: есть шаги и урок.
- [ ] На дашборде каждой роли есть метрики, хотя бы одно кольцо и график за неделю.
- [ ] У роли `decide` уведомление исчезает после решения, а решение появляется в журнале.
- [ ] В журнале роль `decide` может изменить решение.
- [ ] У роли `recommend` работают 👍 и 👎, у роли `chat` чат отвечает и принимает оценки.
- [ ] «Добавить материал» работает, а материал с ролью «для всех» виден всем ролям.
- [ ] Все блоки главной сворачиваются и разворачиваются, чат при этом не очищается.
- [ ] Если подключён `CHAT_WEBHOOK` — чат отвечает живой моделью, а на вопрос вне базы пишет «передаю эксперту».
- [ ] «Сбросить демо» в журнале возвращает портал в исходное состояние.
- [ ] В консоли браузера нет ошибок (F12 → Console).

## Частые ошибки
- **Портал не открылся (пустой экран).** В `CONFIG` сломалась запятая или кавычка.
  Откройте консоль F12, там будет номер строки. Или попросите модель проверить JSON-синтаксис блока.
- **Роль без агентов.** У агента в `roles` должен быть `id` этой роли.
- **Нет графика.** В `week` должен быть массив из 7 чисел на каждую роль.
- **Кольцо показывает число больше 100.** Для `donut` нужен процент от 0 до 100.
- **Чат пишет «Агент сейчас недоступен».** Воркфлоу не активен, URL тестовый (`/webhook-test/`) вместо Production,
  нет учётных данных OpenAI или закончился баланс. В n8n откройте **Executions** — там будет причина.
- **Уведомления партнёра кончились после репетиции.** Журнал → «Сбросить демо».
