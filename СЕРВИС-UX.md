# Сервис «Ролики» — как я вижу устройство и интерфейс

Предложение по веб-сервису, который делает то, что мы девять раз делали
перепиской: из дубля и дорожки собирает вертикальный ролик с анимированной
графикой, режет на части и отдаёт файлы.

Этот файл — **редактируемый исходник предложения**. Правьте прямо здесь.

---

## 1. Главная мысль

**LLM предлагает — считают и решают проверки.**

За девять роликов ни одна ошибка не была ошибкой «плохо придумал». Все были
ошибками измерения и синхронности: чужой дубль, подпись у края кадра, две
иконки на голове говорящего, пустой кадр между сценами, обрыв вместо
кроссфейда. Ни одну из них нельзя доверить модели — они ловятся замером.

Поэтому в сервисе разделение жёсткое:

| Делает OpenAI | Делает код (без модели) |
|---|---|
| черновик раскадровки: что показать и на каком слове | все времена, координаты, кегли, ширины |
| чистка распознавания по сценарию | нарезка субтитров по ширине строки |
| перевод правок словами в структурные изменения | рендер, кодирование, склейка, нарезка |
| подсказка коротких формулировок, когда подпись не влезает | все проверки без исключения |

Если OpenAI недоступен — сервис продолжает работать: раскладка
детерминированная, раскадровку можно собрать руками, проверки на месте.

---

## 2. Что человек делает сейчас и что останется

**Сейчас (одна лекция):** прислать srt, обложку и числа резов → дождаться
скриншотов → написать правки словами → дождаться ZIP → проверить глазами.
От двух до пяти кругов переписки, 30–60 минут ожидания.

**В сервисе:** загрузить дубль и дорожку → посмотреть раскадровку → нажать
«Собрать» → забрать части. Правки — там же, где раскадровка.

Что **не** меняется: решение об утверждении раскадровки остаётся за
человеком. Сервис не должен рендерить неутверждённое — рендер стоит 10 минут.

## 3. Экраны

### 3.1. «Ролики» — список

Плитки: кадр из ролика, название, статус, на каких правилах собран.
Статусы: `черновик` · `ждёт решения (3 замечания)` · `собирается 6:12` ·
`готово` · `выпущено`.

Действия: «Новый ролик», «Открыть», «Повторить как этот» (копирует настройки),
«Скачать ещё раз».

### 3.2. «Материалы» — вход

Четыре зоны: **дубль** (MOV/MP4), **дорожка** (SRT), **обложка** (PNG),
**сценарий** (текст озвучки — по нему чинится распознавание).
Плюс поля: слайды лекции, числа резов («каждые N секунд» или список).

**Проверки входа сразу, до всего остального:**

- **дорожка от этого дубля?** Первые 40 секунд дубля распознаются на месте и
  сравниваются с началом SRT. Совпадение ниже 70% → красная плашка «похоже,
  это другой дубль». Это ровно та ошибка, что стоила нам переделки седьмого
  ролика: чужой srt начинался на 2.70 вместо 0.78, и вся графика ехала.
- длительность, частота кадров, разрешение, поворот;
- обложка 1080×1920 и куда на ней можно положить «Часть N» (замер яркости —
  как я делал руками для девятого);
- резы: попадают ли в паузу дорожки и не рвут ли субтитр.

Каждая находка — с предложением: «сдвинуть рез на 41.9» и кнопкой «Применить».

### 3.3. «Раскадровка» — главный экран

Три зоны:

```
┌──────────────┬────────────────────────────┬──────────────┐
│ СЦЕНЫ        │   КАДР 1080×1920           │ ИНСПЕКТОР    │
│ (лента)      │   (реальный кадр дубля     │              │
│              │    + графика поверх)       │ тип сцены    │
│ 1 0.9–8.5    │                            │ подписи      │
│ 2 8.6–11.4 ▲ │   [превью, играет]         │ времена      │
│ 3 12.0–17.6  │                            │ значки       │
│ …            │   ▶ ──────●────────────    │ цвет         │
├──────────────┴────────────────────────────┴──────────────┤
│ ЗАМЕЧАНИЯ: 2 · «Мыслить как архитектор» — поле 49 (<60)  │
│ ПРАВКА СЛОВАМИ: [ две иконки — широкой парой        ] ⏎  │
└───────────────────────────────────────────────────────────┘
```

Ключевое: **превью играет, а не показывает статичный кадр.** Две последние
пойманные вами ошибки — пустой кадр между сценами и обрыв вместо кроссфейда —
на статичном кадре не видны вообще. Поэтому в превью есть воспроизведение и
«прокрутка по стыкам» — кнопка, которая проигрывает только переходы, по
полторы секунды каждый.

Под каждой сценой написано, **почему она здесь**: фраза дорожки, к которой
она привязана.

Правка словами работает как в переписке: пишете «две иконки — широкой парой»,
сервис показывает, что именно изменит (какие сцены, какие числа), вы
подтверждаете. И сразу предлагает: «Сделать это правилом для всех роликов?»

### 3.4. «Сборка» — очередь

Этапы с честным прогрессом и оценкой: страница → проверки → рендер кадров
(6 мин) → кодирование слоёв (3 мин) → склейка с дублем → нарезка → архив.

Вкладку можно закрыть. Задача переживает перезапуск сервиса: каждый этап
атомарен, при падении возобновляется с последнего завершённого. Отмена
останавливает на границе этапа.

### 3.5. «Готово»

Части с плеерами, обложки, отчёт проверок, кнопки «Скачать всё», «Скачать
часть», «Пересобрать». Плюс кнопка **«Выпущено»** — после неё файлы
замораживаются: пересборка создаёт новую версию, а не переписывает выпущенное.

### 3.6. «Правила» — то, что вы правите

Свод правил как данные, а не как текст в голове ассистента. Два вида:

**Измеримое правило** — с числом и проверкой:

```
Зона графики             238…630        ✓ проверяется
Минимальный кегль        24 px          ✓ проверяется
Зазор между подписями    18 px          ✓ проверяется
Значков в разлёте        4 с каждой     ✓ проверяется
Пара: центры кружков     246 и 834      ✓ проверяется
Пустой кадр между сцен.  запрещён       ✓ проверяется
```

Меняете число — меняется и генерация, и проверка. **Одно место, а не два:**
рендер читает те же значения, иначе превью зелёное, а файл кривой.

**Правило-текст** — то, что числом не выражается: «в кадре ИИ, а не AI»,
«кольцо — не украшение», «приглушённый кадр в ролике один». Уходит в промт
модели и честно помечено `не проверяется автоматически`.

У каждого правила: откуда взялось (ваша цитата или замер), с какого ролика
действует, кнопка «Проверить на прошлых роликах».

## 4. Что делать, когда проверка не прошла

Три кнопки, и у каждой понятный итог:

1. **«Починить»** — когда починка детерминированная: кегль по замеру, ширина
   колонки, сдвиг реза в паузу. Показывает, что именно изменит.
2. **«Поправить руками»** — открывает инспектор на нужной сцене.
3. **«Принять как есть»** — только с показом последствия: «текст выйдет за
   зону на 34px и наедет на соседнюю подпись». Без этого показа кнопка
   превращается в тихий брак с вашей подписью.

Если починка одной проверки ломает другую — сервис говорит об этом до, а не
после: «уменьшение кегля до 23 нарушит правило „минимум 24“».

---

## 5. Версия ролика — это слепок

Каждая сборка запоминает: дубль (хэш), дорожку (хэш), обложку, версию правил,
версию шрифта, версию ffmpeg, версию модели, версию кода конвейера.

Отсюда:

- «вернуться к прошлому варианту» возвращает **тот же** вариант, а не похожий;
- при обновлении шрифта или ffmpeg сервис предупреждает: «этот ролик собран на
  Montserrat 2.1, сейчас 2.3 — пересборка изменит 44 подписи»;
- переснятая озвучка не ломает работу: новый SRT сверяется со старым по
  тексту, правки переносятся по словам, а не по номерам реплик, и показывается
  «перенесено 31, потеряно 4 — вот они».

## 6. Деньги и отказы OpenAI

- счётчик «этот ролик стоил N рублей», лимит на ролик и на месяц;
- ретраи с задержкой, понятная ошибка вместо пустого экрана;
- **режим без модели**: раскладка и проверки работают, черновик собирается
  детерминированно, в шапке честная плашка «модель недоступна»;
- пересборка на новых правилах не зовёт модель вообще — она детерминированная
  и бесплатная (иначе кнопка «проверить на прошлых роликах» будет разорять).

## 7. Что останется мне (в переписке)

Честно, чтобы не было ожиданий:

- новый **тип элемента** (кольцо, столбики, сетка, стрелка нового вида);
- изменение анимации и правил самой сборки страницы;
- нестандартный ролик, который не ложится в шаблоны;
- разбор поломки конвейера.

Сервис закрывает **повторяемое**: девять роликов одной серии, десятый,
одиннадцатый. Для этого есть аварийный выход: на каждом шаге можно скачать
промежуточное (SRT, раскадровку файлом, слой отдельной дорожкой) и загрузить
своё — тогда сервис не тупик.

## 8. Порядок работ

| Этап | Что появляется | Чем полезно сразу |
|---|---|---|
| **1. Конвейер** (~неделя) | загрузка, автораскадровка, экран утверждения, очередь сборки, скачивание | уже не нужна переписка на типовой ролик |
| **2. Правила и проверки** (~неделя) | правила как данные, проверки в интерфейсе, кнопки починки | ошибки перестают доходить до вас |
| **3. Правки словами и версии** (~неделя) | композер правок, слепки версий, регресс на прошлых роликах | правки без ручного редактирования полей |

После первого этапа сервисом уже можно пользоваться — остальное добавляется
не ломая.

---

## 9. Из чего собрано

- **бэкенд** — Python (FastAPI): весь существующий конвейер уже на Python и
  shell, переписывать нечего;
- **очередь** — отдельный процесс-работник, задачи в базе; на VM это ещё один
  systemd-юнит рядом с нынешними;
- **фронт** — одна страница, без сборки, как остальные страницы проекта;
- **рендер** — тот же Playwright + Chromium, тот же `render_overlay.py`;
- **видео** — тот же ffmpeg, те же `собрать.sh` и `нарезать.sh`;
- **OpenAI** — один модуль с лимитом, кэшем и режимом «без модели»;
- **хранение** — папка на ролик, ровно как сейчас `overlay-*`: всё, что
  сервис делает, остаётся обычными файлами, которые можно забрать и собрать
  руками.

Ничего из работающего не выбрасывается — сервис надевается сверху.
